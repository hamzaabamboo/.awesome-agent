## Failure patterns and root causes

1. **Self-blocking hand-back.** Turns ended on "blocked until you…", for example approving full-screen control, restarting an app, freeing disk, entering values in the user's own Chrome, or posting a message. The user's standing position is that the agent is never blocked. Root cause: hard prohibitions in `core_profile.md` (no `open`, no system services, never drive the real Chrome, push only "this turn", never run on a full volume) were applied as stop conditions even after the user explicitly asked for that action in the session.
2. **End-of-turn questions the agent could answer itself.** Examples: whether to copy the new VRM into the app branches, whether to post instructions or hand over the text, whether to deploy after the user had already said deploy. Root cause: the STOP & ASK and grill rules had no test for "answerable from the request, repo or a sensible default", and nothing required continuing other work while a real question was pending.
3. **Unverified completion reports.** Common closing lines were "browser unverified", "no checks run", "device speed remains unverified" and "pass with limitation". The user accepts only pass or fail backed by the real runtime.
4. **Disk space as a stop reason.** Agents halted builds and browser checks at 2–5 GiB free and cited a "full-volume rule". The user expects the agent to free space itself (own build outputs, `node_modules`, stale worktrees, agent-browser sessions, `mo clean`) and keep going.
5. **Describing instead of showing.** Agents returned paths, or `! open -R` suggestions, when the user asked for Finder, the browser, a video or a page. They also skipped QR codes for phone steps.
6. **Wrap-up means finish.** Requests to wrap up or finish remaining work produced lists of open items instead of finished items, with branches unmerged, PRs left open and worktrees left behind (twenty at one point).
7. **Serial, manual data work.** Agents fetched entities one at a time, fixed records by hand, and capped fan-out themselves after the user asked for full concurrency.
8. **Feature loss in redesigns.** Filters, per-member coloring, graphs and prior layouts disappeared during UI rework. Debug or "unconfirmed" internal state leaked into user-facing pages.
9. **Curation by script output.** Setlist and tagging work dumped raw script results with domain errors (wrong units, wrong event types, invented narrative) instead of the agent judging each item.
10. **Ad-hoc workarounds instead of fixing the skill.** When a skill lacked a step, agents patched around it per run.
11. **Idle and unnamed parallel sessions.** Sessions idled with backlog work available, ran their own ticks, and went unnamed, so the user could not tell which session was doing what.
12. **Language and format drift.** Replies came in Japanese after English input, and the daily-report and copy formats were wrong.
13. **Codex memory citation blocks** (`<oai-mem-citation>`) leaked into user-facing replies. This is Codex harness output; it is not controlled by these instructions.

## Changes applied

`shared/core_profile.md`:

- Soft-default override: a session request beats guidance worded as a preference; never/must/always rules and project protocol (required tests, evidence, branch naming, review steps) are not soft defaults.
- STOP & ASK: defines "missing" (not on disk, in the repo, in the session or in a queryable service), bans answerable questions, and requires work to continue while a real question is pending.
- Push/deploy authorization: a direct push/ship/deploy/merge request covers later actions of the same kind for the same task in the session. A PR request authorizes only pushing the PR branch.
- System services: developer tooling (Docker Desktop, VPN client, emulators, local databases) is not a system service and may be started without asking.
- `open`: a request to reveal, locate, show or open something in a named app counts as an explicit request. The agent runs the command itself instead of handing back a command.
- Disk: not a stop or ask reason unless cleanup leaves under 1 GiB free. Under 5 GiB, the agent frees its own artifacts. If that still leaves under 5 GiB, it runs `mo clean` (dry-run first, abort on any sudo or password prompt), then continues. `mo clean` is a stated standing exception, for cache, temp and app-log cleanup only, to the system-touch rule and SCOPE LOCK; it never covers user data, project logs or source.
- New "Recurring failures" block: no blocked/question turn-ends while in-scope work remains, in-session requests beat soft defaults; turn-scoped rules stay per-request, with push/ship/deploy/merge as the only session-wide reading; data deletion, secrets, audio/keychain/sudo, macOS automation and outbound reporting stay absolute, verify-before-report (consistent with NO PROXY COMPLETION), numeric status, wrap-up means finish, bulk over one-by-one, show don't describe, named sessions, feature-preserving redesigns, agent as curator, fix the skill.

`shared/local-skills/get-your-shit-together/references/user-demands.md`: section 21 records the same demands for GYST. Existing lines were also reconciled with it. §1 item 11 and the §10 push line now point to the session-scoped push authorization. The §8 serial-work and one-command lines carve out independent fan-out and single bulk scripts. In §14, the `open` line gains the developer-tooling and reveal/show cases. The §14 rule against starting or stopping servers is reversed: unrelated servers stay untouched, and project dev servers and developer tooling are now started by the agent. The §4 finish-the-chain line and the §10 branch-hygiene line now defer to §21 for push/deploy. §1 item 1 and the §6 investigation line now forbid asking only for information that is discoverable, with a pointer to the §21 exceptions. The table of contents lists §21.

`shared/skill_system.md`: the `check` routing line defers to the profile push rule, and the antislop unresolved-mode question no longer ends the turn; it gates only the antislop-dependent UI output and explicitly overrides the antislop skill's "end the response" instruction.

`analysis/agent-log-pain-points/extract.mjs`: reads `.jsonl.zst` through `zstd -dcq`; scans the whole `~/.codex/sessions` tree instead of only `2026/`; selects Codex and Claude session files by mtime ≥ `SINCE` only (no end bound; messages are filtered by timestamp); requires `SINCE` and `UNTIL` (no defaults); takes the output directory from `OUT_DIR`.

New scripts in `analysis/agent-log-pain-points/`: `pairs.mjs` (pairs keyword-matched corrections with the preceding agent reply), `classify-pairs.mjs` (seven agent-behavior classes), `bucket-messages.mjs` (fourteen user-correction buckets).

## Harness repair (2026-11-04)

The audit's own evidence showed that written rules were not enough: the instructions already said to just do the work and not to ask, and agents read them and stopped anyway. The same failure then repeated inside this audit. The council review ran 22 rounds because every finding was answered with another clause in the profile, each clause created the next contradiction, and nothing bounded the loop.

The repair moves the most frequent failure from text into the harness:

- `shared/hooks/no_self_block.py` is a Stop hook. It judges only the ending of the final message: the last 400 characters, after removing quoted and code spans and Markdown emphasis markers and normalizing curly apostrophes. If that ending asks permission or offers options, declares itself blocked or waiting on the user, or reports work as unverified or untested, the hook blocks the stop once. For the blocked and unverified checks, a match preceded closely by a negation in the same sentence ("nothing is unverified") or followed by none/nothing/0/a dash ("Blocked: none", "Unverified: 0") is ignored, as is a zero count before the word ("0 untested"), and "not verified/tested" counts only at the end of a clause; questions and offers are never exempted. It catches only the listed phrasings; a plain courtesy line with no question or offer, such as an invitation to report issues, passes by design. It tells the agent to do the in-scope work, or to keep only a genuine user-only blocker stated in one line. `stop_hook_active` limits it to one extra round.
- Claude Code: symlinked to `~/.claude/hooks/no_self_block.py` and registered as a second `Stop` hook in `~/.claude/settings.json`; the existing hooks are unchanged.
- Codex: `~/.codex/hooks.json` is a symlink to `shared/hooks/codex-hooks.json`, which uses the same script. Codex 0.166 uses the same Stop input (`stop_hook_active`, `last_assistant_message`) and output (`decision: block`) as Claude Code.

Verification:

- Replay: `tests/test_no_self_block.sh` (47 cases) covers seven agent replies from the audit sample, seventeen more failure phrasings (including curly-apostrophe forms, Markdown-bold endings such as a bold "Blocked" label, a "Blocked:" ending after a sentence containing "not", and questions that follow "No errors found" or "Nothing else changed") and one transcript-fallback case, which must block. It also covers clean finishes, quoted or code-span mentions, past-tense or negated mentions, code descriptions that use "not verified" mid-clause, a failure phrase early in a long otherwise-clean message, the `stop_hook_active` guard, and malformed input (non-object JSON, non-string message, null or missing transcript), which must pass, as must a courtesy line such as an invitation to say so if anything looks off. The quoted-span exemption was added after the hook fired on the steering agent's own summary, which quoted incident phrases.
- Live Claude Code headless run: a reply ending "Should I deploy it?" was blocked by the hook and rewritten as a factual status.
- Live Codex run with `--dangerously-bypass-hook-trust`: the hook ran, logged "Stop Blocked", then completed on the guarded second stop.

Open items:

- Codex runs hooks only after the user trusts them in Codex's own approval prompt. Until then the hook is installed but inactive in Codex.
- Not part of this repair: `~/.claude/hooks/block_pr_merge.py` blocks `gh pr merge` on every project, including the personal repos where the user explicitly authorizes merges. It may explain some merge-related corrections. No specific incident was traced to it.

## Known gaps


- Claude transcripts before 2026-10-08 are deleted. September findings come from Codex only.
- Manual reading step: messages longer than 700 characters were truncated in the compact reading view (first 550 + last 150 characters).
- The 1,541 pairs are a biased sample: `pairs.mjs` keeps only user messages under 600 characters that match a fixed, case-sensitive keyword list: `FUCK`, `SHIT`, `JESUS`, `FFS`, `ZZZ`, `???`, `WHAT DID I`, `DID YOU`, `WHY ARE YOU`, `WHY THE`, `SKILL ISSUE`, `HELLO`, `BITCH`, de-duplicated on the first 200 characters. Calm or lowercase corrections are not counted. "Claimed done" means the reply contained a done or verified claim, not that the claim was proven false; "question" means one of the listed phrases ("Should I", "Shall I", "May I", "Want me to", "Do you want", "Would you like", "Which one/option … ?", "confirm/approve/Let me know/Reply with … ?", "say so", "say if you want"). Only the last 700 characters of the preceding agent reply are stored and classified, and the class patterns are loose (for example, "disk" also matches the bare word "volume"). The agent-behavior classes are keyword matches and can overlap.
- Category counts come from keyword buckets and overlap. The failure patterns come from reading, not from the counts.
